# 目标检测评测指标详解

本文档以学术化定义为主体、口语化解释为辅助，系统梳理目标检测评测的核心概念， 说明工具集（YOLO 口径）与 COCO API 口径的差异。

工具集实现见 `detection_track_toolkit/utils/metric_utils/`。

数学符号约定：设真实目标集合为 $\mathcal{G}$，预测框集合为 $\mathcal{D}$； 匹配函数 $M(d) \in \mathcal{G} \cup \{\varnothing\}$ 表示预测 $d$ 匹配到的真实目标$\varnothing$ 为未匹配）。

---

## 1. 基本概念

### 1.1 TP / FP / FN / TN 的形式化定义

给定匹配 IoU 阈值 $\tau$，对每个预测 $d$，若存在真实目标 $g$ 使
$\text{IoU}(d, g) \geq \tau$ 且 $g$ 未被其他更高置信度的预测占用，则 $M(d)=g$。
据此定义四类基本量：

$$
\begin{aligned}
\text{TP} &= \left| \{ d \in \mathcal{D} : M(d) \neq \varnothing \} \right| \\
\text{FP} &= \left| \{ d \in \mathcal{D} : M(d) = \varnothing \} \right| \\
\text{FN} &= \left| \{ g \in \mathcal{G} : M^{-1}(g) = \varnothing \} \right| \\
\text{TN} &= \left| \{ \text{阴性区域} \} \right| - \text{FP}
\end{aligned}
$$


口语化：**TP 是画对了的框，FP 是乱画的框，FN 是漏掉的真实目标**。

**关于 TN（True Negative，真阴性）**：在二分类问题中，TN 表示"真实为阴性且被预测
为阴性"的样本数，与 TP/FP/FN 共同构成完整四元组。但在目标检测中，阴性概念对应的是
"图像中所有不含目标的背景区域"——该区域没有自然的离散化方式，**TN 是无界且无意义的**，
因此检测的指标体系只使用 TP/FP/FN 三项，不使用 TN，也不计算准确率（Accuracy）。
这是检测评测与分类评测的根本差异之一。

### 1.2 Precision / Recall / F1

$$
\begin{aligned}
P &= \frac{TP}{TP+FP} \\
R &= \frac{TP}{TP+FN} \\
F_1 &= \frac{2PR}{P+R}
\end{aligned}
$$


- $P$（准确率）：预测框中正确命中的比例——"不乱画"；
- $R$（召回率）：真实目标中被找到的比例——"不漏检"；
- $F_1$：二者调和平均，单独一项高无意义，**两者兼顾时 $F_1$ 才高**。

$P$ 与 $R$ 天然构成权衡（trade-off）：置信度阈值 $\theta$ 升高 → $P \uparrow, R \downarrow$；
$\theta$ 降低 → $P \downarrow, R \uparrow$。$F_1$ 曲线即刻画该权衡，见第 4 节。

### 1.3 混淆矩阵：0/1 二分类版与检测版

**0/1 二分类混淆矩阵**（分类任务的标准形态，四元组 TP/FP/FN/TN 的表格化，
行 = 预测类别，列 = 真实类别）：

| 预测 \ 真实 | 阳性 | 阴性 |
|:---:|:---:|:---:|
| **阳性** | **TP**：真实阳性且被预测为阳性（命中） | **FP**：真实阴性但被预测为阳性（误报） |
| **阴性** | **FN**：真实阳性但被预测为阴性（漏报） | **TN**：真实阴性且被预测为阴性（正确拒绝） |

**检测版混淆矩阵**：目标检测在分类混淆矩阵基础上引入虚拟的"背景"类别，
用于归集匹配阶段的两类残差（检测任务中 TN 无界无意义，故不出现）。
示例（2 类检测，行 = 预测类别，列 = 真实类别）：

| 预测 \ 真实 | person | car | 背景(误检) |
|:---:|:---:|:---:|:---:|
| **person** | 2 | 0 | 0 |
| **car** | 0 | 0 | 0 |
| **背景(漏检)** | 0 | 0 | 0 |


| 区域 | 含义 |
|---|---|
| 对角线 | 正确检测（预测类别 $c$ 命中真实类别 $c$） |
| 非对角真实类别区 | 类别混淆（预测 $c_1$ 命中真实 $c_2$ 的框） |
| 最后一列"背景(误检)" | 各类别误检分布（$M(d)=\varnothing$ 的预测按其类别归入） |
| 最后一行"背景(漏检)" | 各类别漏检分布（未被匹配的真实目标按其类别归入） |
| 右下角 | 恒为 0（一个框不可能同时属于两种残差） |

学术化表述：混淆矩阵 $\mathbf{C} \in \mathbb{Z}^{(N+1)\times(N+1)}$，
$C_{ij} = \left| \{ d : \text{cls}(d)=i,\ \text{cls}(M(d))=j \} \right|$（$i,j \le N$），
$C_{i,N+1}$ 为该类别未匹配预测数（误检），$C_{N+1,j}$ 为该类别未匹配真实数（漏检）。
口语化：**背景不是多出来的类别，是误检和漏检两类错误的归集桶**。

## 2. PR 曲线与 AP 的两种离散计算方式

### 2.1 PR 曲线的构造

将 $\mathcal{D}$ 按置信度降序排列为 $d_1, d_2, \dots, d_{|\mathcal{D}|}$。
对每个前缀 $k$（前 $k$ 个预测全部保留，等价于置信度阈值设在 $d_k$ 与 $d_{k+1}$ 之间），
计算累计量：

$$
\begin{aligned}
TP_k &= \sum_{i \le k} [M(d_i) \neq \varnothing] \\
FP_k &= k - TP_k \\
P_k &= \frac{TP_k}{k} \\
R_k &= \frac{TP_k}{|\mathcal{G}|}
\end{aligned}
$$


点集 $\{ (R_k, P_k) \}$ 即 PR 曲线——它完整刻画"阈值从高扫到低时准与全的此消彼长"。

### 2.2 AP 的形式化定义

AP 定义为 PR 曲线的面积：

$$
AP = \int_0^1 P(R)\, dR
$$

其中 $P(R)$ 为单调化包络：$P(R) = \max_{R' \ge R} P(R')$（后向最大单调化，
保证曲线随 $R$ 增大单调不增，消除离散点抖动）。

离散实现存在两种主流方式，**二者对同一组预测给出不同数值**：

**方式一：梯形积分（trapezoidal rule）——YOLO/ultralytics 口径**

$$
AP_{\text{trap}} = \sum_{k} (R_{k+1} - R_k) \cdot \frac{P(R_k) + P(R_{k+1})}{2}
$$

以相邻原始采样点的梯形面积之和逼近曲线下面积。

**方式二：101 点插值（interpolation）——COCO API 口径**

$$
\begin{aligned}
AP_{101} &= \frac{1}{101} \sum_{r \in \{0,\ 0.01,\ \dots,\ 1\}} P_{\text{interp}}(r) \\
P_{\text{interp}}(r) &= \max_{R' \ge r} P(R')
\end{aligned}
$$


在 Recall 轴上取 101 个等距锚点，取每个锚点右侧的最大精度，
再对 101 个值做简单平均（零阶积分近似）。

**两种方式差异的直观解释**：101 点插值对曲线的稀疏/抖动区域更保守
（锚点处取右端最大值后均匀平均），同数据下通常略低于梯形积分，差值一般在
小数点后两位量级，属正常口径差异，**不代表任一实现有误**。

### 2.3 mAP@0.5 与 mAP@0.5:0.95

匹配阈值 $\tau$ 不同，PR 曲线与 AP 随之不同：

$$
\begin{aligned}
\text{mAP@0.5} &= AP\big|_{\tau = 0.5} \\
\text{mAP@0.5:0.95} &= \frac{1}{10} \sum_{\tau \in \{0.5,\,0.55,\,\dots,\,0.95\}} AP\big|_{\tau}
\end{aligned}
$$


- **mAP@0.5**：$\text{IoU} \ge 0.5$ 即算命中——宽松标准，衡量"找没找到"；
- **mAP@0.5:0.95**：十档 IoU 下 AP 的均值——严格标准，衡量"框得准不准"，对定位精度敏感。

## 3. 推理阶段 NMS 的 IoU 阈值 与 评测阶段 AP 的 IoU 阈值（易混淆点）

两个同名参数作用于**完全不同的对象对**，数值选取相互独立：

| | NMS IoU 阈值（预测阶段） | AP 匹配 IoU 阈值（评测阶段） |
|---|---|---|
| **作用对象** | 预测框 **对预测框**（$d_i$ vs $d_j$） | 预测框 **对真实框**（$d$ vs $g$） |
| **作用** | 抑制：若 $\text{IoU}(d_i, d_j) \ge \theta_{\text{nms}}$ 且 $d_i$ 置信度低，则删除 $d_i$ | 判定：若 $\text{IoU}(d, g) \ge \tau$，则 $d$ 可计为 $g$ 的命中 |
| **影响** | 决定"**输出哪些框**"（预测集合 $\mathcal{D}$ 的构成） | 决定"**什么算命中**"（TP/FP 的判定标准） |
| **取值示例** | ultralytics val 默认 0.7 | mAP@0.5:0.95 的 $\tau \in \{0.5, \dots, 0.95\}$ 十档 |

学术化表述：NMS 阈值 $\theta_{\text{nms}}$ 定义预测集合 $\mathcal{D}$ 本身
（$\mathcal{D} = \text{NMS}(\mathcal{D}_{\text{raw}}; \theta_{\text{nms}}, \theta_{\text{conf}})$），
而 AP 阈值 $\tau$ 定义评测的匹配算子 $M_\tau$。前者改变输入，后者改变度量；
$\text{mAP}(\tau)$ 中的 $\tau$ 与 $\theta_{\text{nms}}$ 无任何数值耦合关系。

口语化：**NMS 的 IoU 是"两个框重叠太多就删掉一个"（框 vs 框），
AP 的 IoU 是"画得离真实框多近才算画对"（框 vs 真值）**。你把 NMS 设成 0.5 还是 0.7，
影响的是喂给评测的框集合；而评测用的 0.5~0.95 十档是固定的评分标准，两者互不干扰。
常见的混淆是以为"评测阈值 = 推理时设的 IoU 阈值"——不是的，推理阈值改完，
AP 十档还是那十档。

## 4. P/R/F1 取值口径：学术化与口语化双表述

PR 曲线是连续对象，而 $P/R/F_1$ 是三个**单值**——单值必须指定取曲线的哪一点。
存在两种主流口径：

### 4.1 学术化表述

设置信度阈值 $\theta \in [0,1]$，令 $TP(\theta), FP(\theta), FN(\theta)$ 为
保留置信度不低于 $\theta$ 的预测时的累计量，则
$P(\theta), R(\theta), F_1(\theta)$ 均为 $\theta$ 的函数。

**口径 A：末点取值（end-point）**

$$
\begin{aligned}
P_{\text{end}} &= P(\theta_{\text{conf}}) \\
R_{\text{end}} &= R(\theta_{\text{conf}}) \\
F_{1,\text{end}} &= F_1(\theta_{\text{conf}})
\end{aligned}
$$


其中 $\theta_{\text{conf}}$ 为评测时设定的置信度阈值。
该口径**以评测超参数为取值条件**，数值随 $\theta_{\text{conf}}$ 变化。

**口径 B：最大 $F_1$ 工作点取值（max-$F_1$ operating point，ultralytics 现行）**

$$
\begin{aligned}
\theta^{*} &= \arg\max_{\theta} \tilde{F}_1(\theta) \\
P_{\text{report}} &= P(\theta^{*}) \\
R_{\text{report}} &= R(\theta^{*}) \\
F_{1,\text{report}} &= \tilde{F}_1(\theta^{*})
\end{aligned}
$$


其中 $\tilde{F}_1$ 为 $F_1$ 曲线的平滑估计（对置信度轴 1000 点等距重采样后，
以 101 点箱式滤波平滑，再取类平均）。
该口径**以模型自身属性（$F_1$ 曲线的峰值位置）为取值条件**，与评测超参数无关，
表述的是"阈值调至最优时模型可达到的 $P/R$ 上界"。

### 4.2 口语化表述

把全部预测按置信度从高到低排成一队，逐个"入场"算账：

- **末点口径**问的是"**全部入场后**（垃圾框也放进来了），准确率还剩多少？"
  ——conf 阈值放得越低，末点 $P$ 越难看，但模型本身没变。
- **最大 $F_1$ 工作点口径**问的是"**入队到哪一行时准与全兼顾得最好**？取那一行"
  ——只要高置信的框都入队了，队尾有没有垃圾框都影响不了这一行。

**一句话总结**：末点问"放到底线会烂成什么样"，工作点问"阈值调到最优能好到什么程度"。
后者与训练日志（ultralytics）同源，是部署阈值选取的理论起点。

### 4.3 常见误解辨析：工作点不是"过滤未匹配的框"

一个直观但不准确的解读是："最大 $F_1$ 工作点口径就是在评估中把未与 GT 匹配的框
再过滤掉"。正确机制是**按置信度取阈值**，而非按匹配状态过滤：

| | 按匹配过滤（误解） | 按置信度过滤（实际机制） |
|---|---|---|
| 过滤依据 | 是否命中 GT（评测信息） | score 大小（模型自身输出，部署时同样只用它） |
| 低置信的 TP | 保留（已匹配） | 同样被排除 |
| 高置信的 FP | 过滤（未匹配） | 仍然保留 |

**判据（指纹证据）**：若机制是按匹配过滤，所有匹配框均会保留，工作点 $R$ 应等于末点
$R$；实际数据中工作点 $R$（0.9848）低于末点 $R$（0.9965），说明部分已匹配的低置信框
被排除——这正是按置信度过滤的特征。

**合法性说明**：用 GT 决定保留哪些预测再计算指标属于评测作弊（真值介入了预测集合的
构成）；按置信度过滤则是部署时真实发生的操作。因此工作点口径的本质是
"**模拟部署阈值调至最优时的 P/R 表现**"；而 mAP 的积分始终包含 conf 阈值以上的全部框，
工作点只决定从整条曲线上读取哪个点作为上报的 P/R/F1。

**阈值以下框的两类分层**：$\theta^{*}$ 以下的框按对指标的影响可分为两层——

| 类别 | 特征 | 与峰值的关系 | 部署时的处置 |
|---|---|---|---|
| ① 低置信误检框 | 分数远低于 $\theta^{*}$（如 <0.1），绝大多数未匹配 | 离峰值很远，只拖累末点 $P$，对工作点 $P/R/F_1$ 与 mAP 影响微乎其微 | 默认丢弃，任何合理阈值都不会放进来 |
| ② 权衡区框 | 分数在 $\theta^{*}$ 附近（如 0.3~0.6），成分混杂：有已匹配的低置信 TP，也有较高置信的 FP | 恰是 $P$ 与 $R$ 此消彼长的区间——放进来 $R \uparrow P \downarrow$，剔出去 $P \uparrow R \downarrow$ | **需要按项目需求人为决策的框** |

**工作点是参考阈值而非部署义务**：$\theta^{*}$ 给出的是"兼顾准与全"的参考起点，
实际部署阈值由业务约束决定——漏检率有红线（宁可多框不能漏人）则下调阈值、
保留更多权衡区框；误报成本高则上调阈值。评测时传 conf=0.001 观察全召回区间的
表现是合法的评测姿势，且此时上报的 $P/R/F_1$ 仍为工作点的值，不受 conf 影响。

**术语精确化**：严格说"F1 峰值过滤框"并不准确——峰值本身不做任何过滤，
它只决定**从 PR 曲线上读取哪个点**；真实的过滤动作发生在部署时人工设定阈值。
二者的关系是：**工作点告诉你"阈值设在哪最能兼顾 $P$ 和 $R$"，而设不设、设多少，
是部署决策而非评测行为**。

### 4.4 五框算账实例

$|\mathcal{G}|=2$，预测 5 框（按置信度降序）：

| 序号 | 置信度 | $M(d)$ | $TP_k$ | $FP_k$ | $P$ | $R$ | $F_1$ |
|---|---|---|---|---|---|---|---|
| 1 | 0.9 | 命中 | 1 | 0 | 1.0 | 0.5 | 0.67 |
| 2 | 0.8 | 命中 | 2 | 0 | **1.0** | **1.0** | **1.0 ← 峰值** |
| 3 | 0.005 | 未命中 | 2 | 1 | 0.67 | 1.0 | 0.80 |
| 4 | 0.004 | 未命中 | 2 | 2 | 0.5 | 1.0 | 0.67 |
| 5 | 0.003 | 未命中 | 2 | 3 | **0.4** | 1.0 | 0.57 |

- 口径 A（末点，$\theta_{\text{conf}}=0.001$）：第 5 行 → $P=0.4$；
- 口径 B（工作点）：$\theta^{*}$ 落于第 2 行 → $P=1.0, R=1.0$。

$\theta_{\text{conf}}=0.001$ 仅决定"第 3~5 行是否会入队"——它改变口径 A 的末点，
对口径 B 的峰值行无任何影响。

### 4.5 实现细节（ultralytics 同款）

1. **1000 点插值**：真实曲线的横坐标是各框的实际置信度，分布不均匀；
   将 $\theta$ 轴 $[0,1]$ 等距切为 1000 格做线性重采样，定位稳定且便于绘图。
2. **平滑取峰**：$F_1$ 曲线毛刺多，直接 $\arg\max$ 可能落于噪声点；
   以 101 点箱式滤波（每点替换为前后各 50 点的均值）平滑后再取峰。

**澄清**：重采样与平滑仅作用于曲线（用于峰值定位），不改变参与统计的框集合，
也不是任何形式的"过滤"——全部框始终参与 PR 曲线与 mAP 的积分。二者的唯一间接
影响是：平滑后的峰值位置可能相对裸 $\arg\max$ 偏移数格，使工作点阈值 $\theta^{*}$
微移，恰好落在边界上的极少数框会在"计入/不计入上报 $P/R/F_1$"之间切换；
这是峰值定位稳健性的副产品，而非数据筛选。

### 4.6 真实数据对照（2026-09-15 事件）

v5@480 ONNX + 训练数据集（$|\mathcal{G}|=5458$），$\theta_{\text{conf}}=0.001$，NMS iou=0.7：

| 指标 | 口径 A（修复前） | 口径 B（修复后） | 训练日志 |
|---|---|---|---|
| P | 0.6492 | **0.9864** | 0.9861 ✓ |
| R | 0.9965 | 0.9848 | 0.9902 |
| mAP@0.5 | 0.9960 | 0.9960 | 0.9943 ✓ |
| mAP@0.5:0.95 | 0.7112 | 0.7112 | 0.7493* |

\* mAP 为曲线积分，与取值口径无关，两种口径下数值相同；剩余 0.038 差距来自
物理差异（部署导出 480×480 vs 训练 val 640×640 PyTorch 模型）。

## 5. YOLO（ultralytics）口径 vs COCO API 口径

工具集 `--metrics coco,yolo` 同时输出两种口径，数值不同属正常：

| 维度 | YOLO 口径 | COCO API（COCOeval） |
|---|---|---|
| 匹配策略 | 逐图贪心（置信度降序，同类别、未占用、IoU 最大优先） | 同 |
| AP 计算 | 梯形积分（第 2.2 节方式一） | 101 点插值（第 2.2 节方式二） |
| P/R 报告 | 最大 $F_1$ 工作点单值（与 conf 无关） | 不报 P/R，报 **AR**：maxDets=1/10/100 下的平均召回 |
| 区域划分 | 不划分 | 按面积分 small/medium/large，缺失档 AP=-1 |
| maxDets | 无限制 | 每图最多取置信度前 100 个预测 |
| conf 阈值影响 | 截断积分曲线 → 影响 mAP | 同 |

**两边都值得看**：COCO 口径是学术对比的通用语言；YOLO 口径与训练日志同源可比，
且额外提供 P/R/F1/混淆矩阵。

## 6. 与训练日志对齐的检查清单

评测指标与训练日志不一致时，按序排查：

1. **数据集**：评测 val 与训练 val 同一集合？（可快速核对 GT 数量）
2. **模型**：评测 ONNX 与训练日志对应同一实验版本？（v4 vs v5 之类）
3. **输入分辨率**：ONNX 导出 imgsz 与训练 imgsz 一致？（不一致影响 mAP@0.5:0.95）
4. **参数**：conf 与 NMS iou 与训练 val 一致？（ultralytics val 默认 conf=0.001, iou=0.7）
5. **口径**：P/R/F1 是否按最大 $F_1$ 工作点取值？（本工具集已对齐 ultralytics 语义）

## 7. 工具集指标函数速查

| 函数（utils/metric_utils） | 作用 |
|---|---|
| `compute_yolo_metrics(detections, gts, class_names)` | YOLO 口径总入口：返回 (指标字典, 逐类别表, 混淆矩阵表) |
| `match_predictions` | 逐图贪心匹配（同类别 + IoU 最大优先） |
| `compute_ap` | PR 曲线梯形积分（方式一） |
| `ap_per_class` | 逐类别 P/R/F1（最大 $F_1$ 工作点）+ AP 十档 |
| `format_confusion_matrix` | 混淆矩阵表格（行=预测、列=真实、末行=漏检、末列=误检） |
| `eval_coco` / `eval_per_class` | COCOeval 口径评测与逐类别表格 |

**口径备注（2026-11-13 修复后）**

- YOLO 口径整体指标（all 行与 metrics 字典）只按**有 GT 的类别**求均值
  （`np.unique(target_cls)`，与 ultralytics 同款）：仅有预测而无 GT 的类
  不进均值分母——其误检已计入该类 Precision 行与混淆矩阵误检列，
  再进分母属重复计罚；该情形会打印 `[WARN]` 提示；
- `match_predictions` 要求 `iou_thresholds` **单调递增**（第 0 列为
  IoU=0.5 工作点列），非升序在入口显式报错；
- COCO 口径 `eval_per_class` 的 all 行按列剔除 N/A 哨兵（-1，无 GT 类别的
  无定义条目）后求均值（与 pycocotools 全局统计 `s[s>-1]` 同口径），
  逐类行的 -1 仍按 COCO 惯例原样显示。
